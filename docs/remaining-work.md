# 后续工作优先级（2026-09-27）

本页只列本轮回归后仍有证据支持的缺口。已通过的范围和设备记录见[能力矩阵](compatibility.md)及[验证记录](verification.md)。

## 优先完成

1. **把 API 23 设备闭环加入自动回归。** 本轮 JVM 测试、Android Lint 和构建均通过，真实 Android 6 导出却先后触发 `String.codePoints()` 和 `ZipOutputStream(OutputStream, Charset)` 的 `NoSuchMethodError`，留下 0 字节文件。当前已修复并手测 TXT/EPUB/漫画归档；CI 仍只跑单测、Lint 和 APK 构建，没有旧系统设备执行。至少应自动走本地合成书源的导入、搜索、目录、TXT/EPUB 和漫画 ZIP，并检查文件内容。
2. **处理系统文件提供方写入失败后的残留文件。** CBZ 先完成全部图片暂存，网络或图片校验失败不会写不完整归档；TXT/EPUB 和 CBZ 在最终向系统文件 URI 写入或关闭失败时，提供方仍可能留下部分文件。需要明确失败后的删除或保留策略，并用会在写入、关闭处报错的提供方测试。成功后才清除抓取任务的约束应继续保持。
3. **为真实书源补阶段正对照。** 新补的 `java.getStringList`、JSONPath 逐项返回、`java.log`、`java.head(...).cookies()` 均有官方行为或规则语法依据及离线回归，但相应第三方站点尚未在真实请求下走通；一读小说后续还依赖未实现的 `source.putLoginHeader`。按请求、搜索、详情、目录、正文分别记录最深通过阶段，避免把预检或合成夹具当作站点可用。

## 随后推进

4. **扩展 JS 宿主与登录链路时维持受控边界。** `source.putLoginHeader`、更多 DOM/集合方法、复杂 `exploreScreen`、登录交互和 WebView 验证仍是明确的兼容缺口。先取得真实规则及期望输出，再补小范围实现和离线/设备对照；不对受挑战页或付费内容作自动绕过。
5. **处理 Rhino 在 API 23 的稀有标识符路径。** Rhino 1.7.15 的 `TokenStream.isValidIdentifierName` 在 ES6 Unicode 转义标识符路径直调 `String.codePoints()`，Android 6 缺该方法。普通 `<js>result</js>` 已在设备通过；3907 条集合静态筛查未发现确定样本。遇到实际规则或可复现输入时，评估依赖升级或局部修补，再扩大支持声明。
6. **继续拆分 MainActivity 的业务与 UI 状态。** 目前同一 Activity 管理书源导入、搜索、发现、书籍详情、抓取、资源下载和系统文件选择器。`CaptureRunner`、`CaptureStatus`、持久化存储和选择快照已拆出；下一步应把状态恢复、按钮可用性和结果列表绑定放入可单独验证的层，补旋转、进程回收及文件选择器返回的设备回归。
7. **将大书源集合移出 SharedPreferences。** 当前有效书源、订阅和手动书源原文都以 JSON 字符串提交，手动与有效列表可能重复存储；单次导入允许累计 64 MiB，适合将大集合改为有版本的文件或数据库事务，并验证空间不足、进程退出和旧版迁移。当前提交失败会明确报错并保留旧值，但此存储形态仍有容量与启动读取成本。
8. **清理历史资料与发布准备。** 历史 `*-probe.md` 仅表示当时书源快照及网络观察；继续以能力矩阵为当前入口。发布前需要签名、版本策略、应用名称/图标复核、目标 SDK 升级验证，并明确 HTTP 书源的网络策略。Lint 当前仅余目标版本、Gradle 更新与登录页 JavaScript 启用等提示。

旧数据迁移限制：先前版本若已让订阅覆盖了同 ID 的手动书源原文，新版无法凭现存存储还原该原文；新版开始分别保存两种来源，后续订阅移除时会恢复手动定义。
