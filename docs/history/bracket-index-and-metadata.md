# 方括号位置索引与书籍元数据兼容（2026-09-27）

规则样本来自 [AOAOSTAR XIU2 22 源集合](https://legado.aoaostar.com/sources/71e56d4f.json)，本地获取 SHA-256 `24fe11c400ddc8754703ff0c4d8a249baf024da3a15563de805cc134140959a0`；原始 JSON 未提交。得奇小说网、快书网的 `ruleSearch.kind` 均含 `tag.p.0@tag.span[0:1]@text`，前者详情的 `kind` 也使用 `tag.span[0:1]`。官方 [AnalyzeByJSoup.kt](../../../legado/app/src/main/java/io/legado/app/model/analyzeRule/AnalyzeByJSoup.kt) 的 `ElementsSingle` 将 `[0:1]` 解释为**含两端**的两个节点，还支持负数、反向区间、逗号列表、排除和步长；不是 CSS 属性选择器。

此前工程只支持 `.0`、`.-1`、`!0` 形式，方括号写法会选不到节点。现按官方索引行为补了 Java 实现和合成回归，覆盖 `[0:1]`、`[-1:0]`、`[0,2]`、`![1]`、`[1:3:2]`，并以“得奇”真实规则形态验证题材字符串。

第二个独立缺口是结果模型：原先 `ruleSearch.kind/wordCount/lastChapter` 和对应详情规则根本未进入 `BookHit`。现在 `BookHit.genre` 承接书籍题材/状态文本，`wordCount`、`lastChapter` 保存元数据；它们与 `BookHit.kind`（文本/音频/图片等**书源媒体类型**）分开。搜索赋值、详情覆盖/保留、`mainJs` 返回字段都加了 Java 回归；旧构造器仍可用。探针只显示三个字段是否存在，不记录作品正文。
