测试词覆盖三本中文原创网文（《诡秘之主》《斗破苍穹》《凡人修仙传》）和两本中文译名轻小说（《无职转生》《刀剑神域》）。这只是不同类型的搜索探针，并不预设每个轻小说站点都应收录中文原创网文。网页自身说明该书源集主要面向轻小说，对国内原创网络文学另有类别限制。

补充集合的新机制和响应质量诊断见[跨站探针](supplemental-source-probe.md)：番茄小说2 的 HTTP 200 实为 `PARAM_INVALID`，不能算有效 0 命中；阅友小说曾因本工程默认 DOTALL 的替换正则把首章截短，现按官方语义修复并复测。这两例表明成功数量与 HTTP 状态均不能代替规则和正文质量检查。

另见[变量与伪正文探针](variable-and-response-probe.md)：追书小说可走搜索→详情→目录，但服务器给出的首章是升级提示，不能算正文成功；番薯小说暴露并修复对象型 POST body 的本地规划错误，真实请求仍停在 TLS。

[媒体书源探针](media-source-probe.md)覆盖了音频与漫画的另一类伪成功：恋听网播放页曾被当成一个音频资源，现明确报缺少 `sourceRegex` 的 WebView 媒体监听；两条 26 字符音频 API 响应实为“没有该用户”的业务错误；其余 HTTP 403/444、TLS 和异常页面分别归类，均不计作资源下载通过。

[压缩响应与详情初始化探针](gzip-and-init-probe.md)记录了猫眼看书的 JVM gzip 假 0 命中、结构化 `init` 缺口和仍存在的详情业务错误；这是搜索 15 条但不能走到目录/正文的明确例子。

使用本工程 `SourceEngine.search(source, title, 1)`，每次请求间隔 1.5 秒，JVM HTTP 连接/请求超时 12/15 秒。首次探针测《诡秘之主》《无职转生》，后续从管理目录当前快照测另外三词。复测前可运行：

```sh

./gradlew :source-core:liveSourceProbe -PprobeQueries=诡秘之主,斗破苍穹,凡人修仙传,无职转生,刀剑神域
```

`liveSourceProbe` 是手动运行的网络探针，不进入确定性单元测试；它使用 JVM HTTP 客户端，不能代替 Android WebView/登录态测试。实时结果可能随网络、站点防护、账号及上游规则更新变化。不要高频反复运行。

另以经致文学验证 HTTP 200 的页面内容边界：搜索“上门龙婿”返回 1 条，但详情 `/books/609` 是明确“不存在”提示页。修复前伪报详情通过、目录规则失败；现在 JVM/Android 均停在 `DETAIL.ruleBookInfo.init / PAGE_NOT_FOUND`。未得到真实目录，故其 `select/hasClass` 规则尚未验证；无正文及下载。[源哈希、命令和阶段证据](jingzhi-notfound-probe.md)。

再从 128 源集合挑 19 条不同名称书源各搜一次，其中 16 条为此前跨站记录之外的新候选，主要碰到 TLS/EOF、403/404、跨域 301→403 和未完成 302；企鹅听书明确返回 `books=[]/total=0`。有度复测 15 条搜索、详情及目录 107 条，但公开目录的 108 个 HTML 条目里有 2 个同 URL `javascript:` 占位，去重后仍留 1 个，故不称 107 章均可阅读。JVM/Android 探针现均报告占位数；没有新下载。[逐站结果与官方去重依据](additional-cross-site-probe.md)。

另选 24 站分流搜索，其中多数停在 403、TLS/EOF 或非正常响应；可达源暴露两项通用缺口：磨铁的 URL 选项把 `headers` 存成 JSON 对象字符串，旧规划器在发请求前类型转换失败；现 JVM/Android 都能请求，API 此词为明确空列表。宜搜原始目录 API 有 839 条、776 条 `charge=1`，旧工程却因 `@put` 变量未随书传递、JS 引号中的 `{{$.字段}}` 未提前展开而把全部 URL 碰撞成 1 条；修复后 JVM/Android 均为 839 条、VIP 776 条。只验证到公开目录，不读取 `autoBuy=1` 的付费正文，也未新增下载。[源码依据、命令与阶段证据](header-and-search-item-variable-probe.md)。
