# 兼容证据与诊断

对每个问题保留：模型类型、源 ID 与快照哈希、官方基准提交、规则字段、最深成功阶段、首个失败阶段、测试时间/环境、脱敏请求和最小响应夹具。按 `NETWORK`、`AUTH`、`PARSE`、`RULE`、`JS_HOST`、`UNSUPPORTED`、`UNKNOWN` 归因；HTTP 403、登录页、WebView 缺失和真正的零搜索结果不能合并。参见上游[验证矩阵](../../../legadoSkill/docs/rules/validation.md)。

验证顺序按问题选择：官方调用路径 → 脱敏离线正反例 → 本地 HTTP 端到端 → 真实源单阶段复测 → 必要时 Android 差分。每个新支持的子能力要有可重复的离线回归；网页或设备无法访问时记录限制，不把模拟结果写成官方通过。`SUPPORTED` 表示已测试，`PARTIAL` 列明子集，`UNSUPPORTED` 明确拒绝，`UNKNOWN` 表示未测。

当前实现边界以项目[能力矩阵](../../../docs/compatibility.md)为准；新增实测写入[实测记录](../../../docs/live-source-tests.md)。跨站覆盖按不同站点、规则机制和最深成功阶段衡量；单站多本或大量下载只证明对应样本。只有明确需要整书压力验收时，才按项目契约用限速、可续跑的 `batchDownloadProbe` 核对各书 URL、章节缓存、文件大小和 SHA-256；部分书不算完成。

不存储账号、Cookie、Token、付费内容、第三方完整书源或作品正文。请求需要登录、验证码、付费、发布或删除时，只在已有授权范围内验证；无法执行则报告该边界。

本轮 2026-10-22 的规则、持久态和 RSS 扩展使用自造的本地夹具。区分“测试代码已添加”“该测试已执行通过”“Android HTTP 合成阶段通过”与“RSS 网页注入/原生桥通过”；最终统一检查或设备执行未完成时保留待验证。`RssCompatibilityProbeActivity` 仅验证 RSS core 的文章和阅读目标，不覆盖浏览器桥或真实站点。
