# 验证、归因与交付

## 共同证据

只验证用户目标需要的阶段。普通书源观察搜索/发现、详情、目录、正文或资源；RSS 观察分类/搜索、XML/自定义列表、翻页与阅读目标。记录模型、源 ID/版本或哈希、官方基准、时间/环境、触发动作、最深成功阶段、首个失败阶段、脱敏最终请求和预期/实际结果。基址使用实际响应地址；需要时保留编码、规则原始值与最终值。

把 HTTP 错误、登录页、验证码、业务错误页和正常零命中分开，按 `NETWORK`、`AUTH`、`PARSE`、`RULE`、`JS_HOST`、`UNSUPPORTED`、`UNKNOWN` 归因。可选元数据失败与关键导航失败分开报告。结构、规则、阶段、流程四层口径见[书源定义 RFC §6](../../../docs/source-definition.md#6-验证与结果报告)。

## 交付源 JSON

在真实 HTML/JSON 上验证选择器与请求前提；按指定入口交付单对象或数组，核对实体、字段、转义和 URL 选项。附使用页面与时间、已验证阶段、登录/WebView 前提和未验证字段。缺输入时交付与现有证据一致的草案，不补造字段。

区分官方 App 实测、本工程或静态/离线验证、仍待验证；Java 或 Python 模拟结果不能独自证明官方 App 可用。普通书源与 RSS 的类型数字及字段不能互套。

## 引擎兼容验收

按问题选择官方调用路径、离线正反例、本地 HTTP、真实源单阶段和 Android 差分。每个新子能力要有可重复回归；`SUPPORTED` 表示已测，`PARTIAL` 明列子集，`UNSUPPORTED` 明确拒绝，`UNKNOWN` 表示未测。

命令和设备入口见[验证指南](../../../docs/verification.md)。`RssCompatibilityProbeActivity` 只验证 Android HTTP/core 的文章与阅读目标；`RssBrowserProbeActivity` 才验证网页桥子集，均不能证明真实站点通过。最新执行结果和旧设备覆盖范围分别保留，避免混合不同版本的测试数量。

跨站覆盖按独立站点、规则机制、最深成功阶段衡量；单站多书只证明对应样本。只有明确需要整书压力验收时才使用限速、可续跑的 `batchDownloadProbe`，逐本核对不同书 URL、完整章节、文件大小和 SHA-256；部分下载不计完成。

不提交账号、Cookie、Token、第三方完整书源、付费内容或作品正文。敏感交互仅在已有授权范围内执行，无法验证时报告限制。上游[验证指南](../../../legadoSkill/docs/rules/validation.md)可供查询。
